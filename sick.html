SICKServer Info & Check Kit

Every part of the box, in one report.

SICK inventories a Linux server in one pass — CPU and platform, memory per DIMM, disks with SMART health, NVMe wear, RAID and HBA controllers, NICs, GPU and motherboard — as colorized tables or JSON.

$curl -sL https://ba.sh/sick | bash

English report. Run as root (or pipe into sudo bash) for memory modules, SMART and sensors.

Report coverage

What SICK reports.

Section by section, in the order you'd check a new box — each one degrades gracefully when a tool or permission is missing.

System

Hostname, OS, kernel, uptime.

CPU / Platform

Model, cores and threads, frequency, cache, temperature, sockets and NUMA, virtualization, microcode.

Memory

Totals plus a per-DIMM table: size, type, speed, vendor, serial, part number.

Disks / SMART

Mounts, SMART health, power-on hours, temperature, lifetime I/O and defects.

NVMe

Temperature, wear (percentage used), available spare, unsafe shutdowns.

RAID / HBA

mdraid arrays and RAID / HBA controllers, including disks behind MegaRAID.

Network

Link state, speed and duplex, driver or model, masked MAC and IP, error and drop counters.

GPU / Board

Graphics class and model, board vendor and model, BIOS vendor and version.

Health verdict

The report ends with a verdict: problems (✗ SMART failure, reallocated or pending sectors, degraded RAID, ECC errors) and warnings (! wear, temperature, a filesystem ≥ 90% full).

Examples

$curl -sL https://ba.sh/sick | bash

Full report in English.

$curl -sL https://ba.sh/sick | bash -s -- -cn

The same report in Chinese.

$curl -sL https://ba.sh/sick | sudo bash -s -- -y

As root, installing any missing tools first.

$curl -sL https://ba.sh/sick | bash -s -- --json > sick.json

JSON only — for jq, inventories and dashboards.

$curl -sL https://ba.sh/sick | bash -s -- --no-color --no-clear > report.txt

Plain text for a ticket, a forum post or a diff.

$curl -sL https://ba.sh/menu | bash -s -- sick -cn

Through the launcher menu.

Notes

Good to know

Do I need root?

No, but it helps: dmidecode (memory modules, board), SMART and some sensors only answer to root. Without it, SICK still runs and marks what it couldn't read. Use curl -sL https://ba.sh/sick | sudo bash for the full picture.

Which tools does it use?

dmidecode, lshw, smartctl (smartmontools), ethtool, nvme (nvme-cli), jq, lspci (pciutils), sensors (lm-sensors) and lsblk. If some are missing, SICK lists them and asks Y/N before installing; -y installs without asking, --no-install never installs.

Is the report safe to paste publicly?

IP and MAC addresses are masked in the text report. Serial numbers (disks, DIMMs) are shown in full — redact them before you post.

Does it leave anything behind?

No daemon, no config file, no cron job — the script runs from the pipe and exits. If it installed tools, it offers to remove exactly those packages afterwards; --cleanup removes them without asking, --keep-packages keeps them.

Which distributions are supported?

Debian, Ubuntu, Mint; RHEL, CentOS, AlmaLinux, Rocky, CloudLinux, Oracle and Amazon Linux; Fedora; Arch and Manjaro; openSUSE and SLES; Alpine — plus their derivatives. Packages come from apt, dnf, yum, pacman, zypper or apk.
